# Plan 1 · Base de la aplicación — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dejar una aplicación Next.js desplegable con Docker que tenga base de datos, inicio de sesión, roles, gestión de usuarios, historial y configuración de empresa e impuestos. Sobre ella se construirán catálogo, clientes, presupuestos y PDF.

**Architecture:** Monolito Next.js (App Router) con módulos en `src/modules/<módulo>/`. Cada módulo separa `schema.ts` (Zod), `service.ts` (lógica + acceso a datos con Prisma; comprueba permisos), `actions.ts` (Server Actions finas que llaman al servicio) y sus páginas en `src/app`. La autenticación usa Better Auth con el plugin `admin`. Las pruebas usan Vitest contra un PostgreSQL real de desarrollo.

**Tech Stack:** Node 24, pnpm, Next.js 16, React 19, TypeScript 5.9, PostgreSQL 17, Prisma 7 (driver adapter `@prisma/adapter-pg`), Better Auth, Zod 4, Vitest, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-11-06-app-presupuestos-design.md` (secciones 3, 5.1, 5.8, 5.9, 5.11, 5.12)

**Fuera de este plan** (van en planes posteriores): unidades, categorías y margen en el catálogo (plan 2); numeración, conceptos obligatorios y estados (plan 3); Dokploy, HTTPS y copias de seguridad (plan 4).

**Serie de planes:** 1 Base (este) → 2 Catálogo y clientes → 3 Presupuestos (cálculo, conjuntos, editor, emisión, revisiones) → 4 PDF, despliegue en Dokploy y copias de seguridad.

## Global Constraints

- Versiones exactas en `package.json` (sin `^` ni `~`) y `pnpm-lock.yaml` en el repositorio: `next@16.4.5`, `react@19.3.1`, `react-dom@19.3.1`, `typescript@5.9.3`, `prisma@7.10.1`, `@prisma/client@7.10.1`, `@prisma/adapter-pg@7.10.1`, `better-auth@1.7.18`, `zod@4.6.7`, `vitest@5.1.0`, `@types/node@24.19.2`. `"packageManager": "pnpm@12.18.0"`. Se usa TypeScript 5.9 y no 7.x por compatibilidad con Next 16.
- Imagen Docker de Node: `node:24-bookworm-slim`. PostgreSQL: `postgres:17`.
- Identificadores de código, tablas y rutas internas en inglés; textos de interfaz y documentación en español. Rutas visibles en español (`/admin/usuarios`, `/admin/configuracion`).
- Roles exactos: `admin` (Administrador) y `presupuestador` (Presupuestador). No hay registro público (`disableSignUp: true`).
- Los usuarios se desactivan (ban sin caducidad del plugin admin) y nunca se borran.
- Todo permiso se comprueba en servidor, dentro del `service.ts`. La interfaz solo oculta opciones.
- Importes y tipos impositivos en `Decimal` de Prisma (`@db.Decimal`), nunca `Float`. Tipo de impuesto: `@db.Decimal(5,2)`.
- Secretos solo por variables de entorno: `DATABASE_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `DATA_DIR` (directorio persistente para logo y, más adelante, PDF). `.env` fuera de Git y `.env.example` dentro.
- Sin Redis, colas ni servicios externos. PostgreSQL no se publica fuera de la red de Docker en `compose.yaml`.
- No se modifica ni se borra el material original (Word, Excel, PDF, `.msg`).
- Interfaz según la dirección «Esquema unifilar» de `docs/diseno/README.md`. Los tokens de color, tipografía (Archivo, cargada con `next/font/google`) y filetes salen de `docs/diseno/maquetas/isf.css` hacia `src/app/globals.css`. `login.html` y el rail de `listado.html` son la referencia de la Tarea 2; `catalogo.html`, para las tablas y formularios de las Tareas 5 y 6. Persistencia: volúmenes `pgdata` y `appdata` en `compose.yaml` (Tarea 7), y despliegue en Dokploy en el plan 4.

## Review Focus

1. **Usuario desactivado con la sesión abierta:** al desactivarlo debe perder el acceso de inmediato, no al caducar la cookie → prueba en la Tarea 5.
2. **Dejar la aplicación sin administradores:** desactivar o degradar al último administrador activo, incluido uno mismo, debe rechazarse con un mensaje claro → prueba en la Tarea 5.
3. **Un presupuestador llama a una Server Action de administración sin pasar por la interfaz:** debe recibir `ForbiddenError` → pruebas en las Tareas 5 y 6.
4. **Tipo impositivo escrito al estilo español («21,5») o fuera de rango («150»):** «21,5» se acepta y se guarda exacto como 21.50; «150» y «-1» se rechazan → prueba en la Tarea 6.
5. **Logo que no es imagen o es muy grande:** solo PNG/JPEG de ≤ 2 MB (SVG no, para evitar scripts incrustados) → prueba en la Tarea 6.
