- [ ] **Step 2:** Ejecutar `mise x -- pnpm exec vitest run tests/pdf/pdf-content.test.ts`. Resultado esperado: fallan (a) y (c), y las demás pasan.
- [ ] **Step 3: Implementar.** Hay que hacer dos cambios en el tramo final de `paginate`.
  1. **Llevar las filas por bloques.** La fila se lleva junto con lo que la encabeza o la comenta, así que una partida, una subpartida o una nota nunca se separan. El bucle de llevar filas, junto con su `while` de notas, se sustituye por este:
     ```ts
     for (let i = rs.length - 1; i >= from; ) {
       let j = i;
       while (j > from && leads(rs[j - 1], rs[j])) j--; // the block: a row with the heads before it and its note
       const block = rs.slice(j, i + 1);
       const firstBlock = target.children.length === 0;
       target.prepend(...block);
       if (!firstBlock && over(sheet)) { tbody.append(...block); break; } // it fitted on the old sheet before the close
       i = j - 1;
     }
     ```
  2. **Dejar fluir la última hoja si no cabe.** Toda salida que ocurra después de `sheet.append(close)` pasa por `flow(sheet)`, también los dos `return` tempranos. `flow` es un ayudante local: si `over(s)`, pone `s.style.height = "auto"` y `s.style.overflow = "visible"`, y quita `break-inside: avoid` al `.close` para que Chromium lo parta entre páginas. Si la rejilla del `.close` no se parte, se le pone `display: block` solo en ese caso. Lo decide la prueba (c).
